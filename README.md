# خانه‌گی — فروشگاه لوازم خانگی

فروشگاه فارسی RTL با React + TypeScript + Vite و Supabase. این مخزن یک پیاده‌سازی قابل توسعه است؛ فعال‌شدن عملیات واقعی به ساخت پروژه Supabase، اجرای migrationها، تنظیم secrets و پیکربندی درگاه پرداخت وابسته است.

## اجرای محلی

```powershell
npm install
Copy-Item .env.example .env
npm run dev
```

سپس `.env` را ویرایش کنید. تا زمانی که Supabase تنظیم نشده، برنامه با داده‌های نمایشی اجرا می‌شود. برای کاتالوگ واقعی:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
VITE_USE_DEMO_DATA=false
```

کلید `service_role`، کلید درگاه و اسرار سرور را هرگز در `VITE_*` قرار ندهید.

## بررسی

```powershell
npm test
npm run build
```

## اتصال Supabase

**پیش از استقرار:** آخرین فایل مهاجرت `202610210001_admin_security_and_exports.sql` نقش `super_admin`، ساخت اتمیک محصول/موجودی و محدودسازی تغییر وضعیت پرداخت را اضافه می‌کند. ابتدا تمام migrationها را در یک پروژه آزمایشی بررسی و اجرا کنید؛ اجرای migration در این مخزن یا محیط کاربر انجام نشده است.

1. یک پروژه Supabase بسازید.
2. فایل‌های `supabase/migrations` را به ترتیب در محیط آزمایشی اجرا کنید (ترجیحاً با Supabase CLI و migration history).
3. `supabase/seed.sql` را اجرا کنید؛ محصولات واقعی و موجودی باید از پنل یا ابزار واردسازی امن اضافه شوند.
4. در Authentication، روش ورود و URLهای redirect را پیکربندی کنید.
5. حساب مدیر را با روش امن از داشبورد/SQL مورداعتماد به نقش `admin` اضافه کنید؛ هرگز نقش را از کلاینت قابل تغییر نکنید.
6. مقادیر `.env` را تنظیم و `VITE_USE_DEMO_DATA=false` کنید.

### آنچه پیاده‌سازی شده

- کاتالوگ با تلاش برای خواندن محصولات منتشرشده از Supabase و fallback به داده نمایشی در حالت دمو؛ سبد و علاقه‌مندی‌ها در localStorage نگهداری می‌شوند.
- ورود/ثبت‌نام ایمیلی Supabase و فهرست سفارش‌های حساب کاربر.
- فرم checkout که فقط برای کاربر واردشده سفارش می‌سازد؛ تابع `create_order_secure` قیمت و موجودی را از دیتابیس می‌خواند، ردیف‌ها را قفل می‌کند، موجودی را رزرو می‌کند و snapshot سفارش می‌سازد.
- پنل ابتدایی مدیریت محصولات و سفارش‌ها با کنترل نقش‌های RLS؛ محصولات جدید ابتدا draft می‌مانند. خروجی CSV محصولات و سفارش‌ها اضافه شده است. ساخت محصول و موجودی اولیه از RPC تراکنشی انجام می‌شود.
- Edge Function شروع پرداخت fail-closed و Edge Function فید عمومی محصول برای یکپارچه‌سازی بعدی.
- robots.txt و sitemap پایه.

### هنوز نیازمند تنظیم/تکمیل است

- پرداخت آنلاین **متصل نیست**: باید ارائه‌دهنده مشخص (مثلاً زرین‌پال یا به‌پرداخت)، مستندات فعلی، شناسه پذیرنده، callback، امضای درخواست و تأیید سرور انتخاب و پیاده‌سازی شود. Function عمداً URL پرداخت جعلی تولید نمی‌کند و سفارش را paid نمی‌کند.
- فید ترب عمومی‌سازی شده اما فرمت آن **تأیید رسمی ترب نیست**؛ پیش از ثبت باید مستندات فعلی/فرمت اختصاصی پذیرنده بررسی شود. توکن endpoint و `PUBLIC_SITE_URL`/`SUPABASE_SERVICE_ROLE_KEY` را فقط در Secrets سرور تنظیم کنید.
- اتصال نرخ ارز نیازمند منبع داده معتبر، timestamp، محدودیت تازگی و تأیید مدیر است؛ Edge Function قیمت‌گذاری موجود فقط preview است تا وقتی گردش انتشار قیمت امن شود.
- مدیریت محصول فعلاً ایجاد draft و مدیریت وضعیت سفارش را دارد؛ بارگذاری تصویر، مدیریت دسته‌بندی/برند، موجودی، گزارش‌ها، مرجوعی، تخفیف‌ها و audit UI باید تکمیل شوند.
- باید چرخه انقضای رزرو سفارش، هزینه ارسال، کد تخفیف، آزمون همزمانی، rate limiting و مانیتورینگ اضافه شوند.
- SEO برای SPA پایه است؛ sitemap فعلی شامل `YOUR_DOMAIN` است و باید هنگام استقرار با دامنه واقعی تولید شود. برای SEO کامل محصولات SSR/prerender لازم است.

## پرداخت و امنیت

هرگز صرفاً با پارامتر callback مرورگر وضعیت پرداخت را `paid` نکنید. سرور باید از API رسمی درگاه تأیید پرداخت بگیرد و مبلغ/شناسه سفارش را تطبیق دهد. secrets فقط در Supabase Edge Function Secrets نگهداری شوند. RLS و RPC را روی پروژه آزمایشی و با نقش‌های anon/authenticated/admin تست کنید.
